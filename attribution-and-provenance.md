## 3. Status representation rules

To avoid overstating standing, the following usage rules apply to all public text, including
repository READMEs and CVs:

| Situation | Permitted wording |
|---|---|
| Joined the working group, on the mailing list, attends meetings | "Participant, MLCommons AIRR Safety working group" |
| Has approved GitHub submission rights | "Approved contributor access to MLCommons GitHub repositories" |
| Pull request opened, not yet merged | "Submitted a proposal to …" — **not** "Contributor" |
| Contribution merged / adopted / acknowledged | "Contributor, MLCommons AIRR …" |

An open pull request is not a merged contribution, and working-group membership is not contributor
status. These are tracked separately.

## 5. Licensing positions

| Material | License | Note |
|---|---|---|
| Prior working papers | CC BY 4.0 | Already public; unchanged by this submission |
| The three public documents in this submission package | CC BY 4.0 | Intended for public filing |
| Public practice examples | CC BY 4.0 | Consistent with MLCommons' own prompt-set licensing |
| Private official-test candidates | **Not published** | Terms to be set by the receiving channel; see below |

Under the MLCommons Individual CLA, copyright in a contribution remains with the contributor, and
MLCommons receives a non-exclusive licence. The CLA contains no attribution guarantee, which is why
attribution is embedded in the artefacts themselves (§2) rather than requested separately.

The CLA also treats mailing-list and issue-tracker material as contributions unless explicitly
marked otherwise. Material intended to stay outside that scope must be marked **"Not a
Contribution"** at the point of sending.
